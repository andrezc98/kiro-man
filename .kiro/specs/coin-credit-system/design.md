# Design — coin-credit-system

## Overview

Two pure modules model the cabinet: `src/arcade/credits.ts` (the credit arithmetic) and `src/arcade/cabinet.ts` (a reducer over screens), plus `src/arcade/initials.ts` (the initials-entry reducer) and `src/content/facts.ts` (`pickFact`). The browser loop in `src/app/main.ts` turns keyboard input into cabinet events, feeds a `uiTick` event every animation tick (60 Hz, the same fixed-step loop as the engine), and executes the returned effects. Render reads `CabinetState` to draw the screens. The stack is TypeScript strict and Vitest + fast-check, the same as the overview.

## Quality bar / no scope cuts

Every screen and transition in requirements.md is required and polished. P1, P9, and P10 run at ≥ 100 runs, and the edge cases listed below have unit tests. No TODOs.

## APIs

```ts
// credits.ts
export const MAX_CREDITS = 99;
export function insertCoin(credits: number): { credits: number; accepted: boolean };
export function tryStart(credits: number): { credits: number; started: boolean };

// initials.ts
export interface InitialsState { letters: [number, number, number]; cursor: 0|1|2; idle: number; done: boolean }
export type InitialsKey = 'up'|'down'|'left'|'right'|'enter'|{ char: string }|'tick';
export function initialsReduce(s: InitialsState, k: InitialsKey): InitialsState;
export function initialsString(s: InitialsState): string; // always ^[A-Z]{3}$

// cabinet.ts
export type Screen = 'attract'|'playing'|'incident'|'initials'|'highscores';
export interface GameSummary { seed: number; score: number; level: number; bugsEaten: number;
  servicesUsed: Record<PowerKind, number>; lastKiller: EnemyId | null;
  gameOverReason: 'caught'|'timeLimit'|'qa'; inputLog: InputLog; tainted: boolean }
export interface CabinetState { screen: Screen; credits: number; uiTick: number; screenTicks: number;
  insertCoinFlash: number; attractPanel: 'title'|'scores'; summary: GameSummary | null;
  initials: InitialsState | null; lastInitials: string | null; highlightRank: number | null;
  remoteStatus: 'idle'|'submitting'|'verified'|'rejected'|'offline'; remoteDetail: string | null;
  online: boolean; localQualifies: boolean }
// `online` is fixed for the session: main.ts awaits loadConfig() (≤ 2 s) before initialCabinet(apiUrl !== null).
// remoteStatus transitions (binding): reduce sets 'submitting' in the same result that emits submitRemote.
// Suppressed emission: tainted → 'idle'; offline → 'offline'; inputLog.length > 10000 → 'rejected' with remoteDetail 'LOG TOO LONG'.
// Later remoteStatus events (from remoteClient results): ok (any 2xx with {accepted:true,score,level}) → verified;
// rejected (400/413/422) → rejected with remoteDetail = body.error uppercased; http (other non-2xx), network, timeout,
// bad_response (incl. a 2xx with another body) → offline. GET failures only affect the global panel, never `online`.
export type CabinetEvent =
  | { type: 'coin' } | { type: 'start'; seed: number } | { type: 'confirm' }
  | { type: 'gameOver'; summary: GameSummary; qualifies: boolean }
  | { type: 'initialsKey'; key: InitialsKey } | { type: 'uiTick' }
  | { type: 'remoteStatus'; status: CabinetState['remoteStatus']; detail?: string } | { type: 'localSaved'; rank: number | null };
export type Effect =
  | { type: 'sfx'; name: SfxName } | { type: 'startEngine'; seed: number }
  | { type: 'saveLocalScore'; entry: { initials: string; score: number; level: number } }
  | { type: 'submitRemote'; submission: { initials: string; seed: number; inputLog: InputLog; claimedScore: number } };
export function initialCabinet(online: boolean): CabinetState;
export function reduce(s: CabinetState, e: CabinetEvent): { state: CabinetState; effects: Effect[] };
```

`reduce` returns a new object (spread copies) and never mutates its input. Cabinet state is small, so immutability costs nothing and makes P1 and the unit tests simple.

## Key decisions

**The seed is generated by the app, not the reducer.** `start` carries the seed so the reducer stays deterministic. `src/app` computes it as `(crypto.getRandomValues(new Uint32Array(1))[0]) >>> 0`. The app layer is allowed to do that.

**Keyboard → event mapping is per screen (binding).** `src/app/keyboard.ts` exports a pure `mapKey(screen, key): AppAction | null`. On `initials`: `/^[a-zA-Z]$/` → `initialsKey({char})`; ArrowUp/Down/Left/Right → `initialsKey(up|down|left|right)`; Enter → `initialsKey('enter')`; `5` → `coin`; everything else → null. On every other screen: `c`/`C`/`5` → `coin`; `m`/`M` → mute; `p`/`P` → pause (playing only); Arrows and WASD → direction (playing only); Enter → `start(seed)` on attract, `confirm` on incident/highscores. Unit tests in `src/app/keyboard.test.ts` cover C and M on initials.

**Root cause text.** `rootCause(summary)`: `lastKiller !== null` → `"<NAME> CAUGHT KIRO"` with `ENEMY_NAMES = {latency:'LATENCY', throttle:'THROTTLE', coldstart:'COLD START', outage:'OUTAGE'}`; `gameOverReason === 'timeLimit'` → `"SHIFT ENDED (30:00)"`; `'qa'` → `"MANUAL FAILOVER"`. `GameSummary` gains `gameOverReason`.

**Input log cap.** When building `submitRemote`, if `summary.inputLog.length > 10000` the reducer emits no `submitRemote` and sets `remoteStatus = 'rejected'` with `remoteDetail = 'LOG TOO LONG'`. Ticks can't exceed 107999 because the engine ends the game at `MAX_TICKS - 1`.

**Facts content.** `aws-facts.json` is an array of `{ id, service, text, sourceUrl }`. `facts.ts` validates at module load (throws `Error("aws-facts.json invalid: ...")`): `id` unique and `^[a-z0-9-]+$`; `service ∈ CATALOG_ORDER ∪ {'dynamodb'}`; `text` 1..120 chars and every char of `text.toUpperCase()` is in `FONT_GLYPHS` (exported from `src/content/glyphs.ts`, a pure list that `src/render/font.ts` must cover — a unit test asserts the font has a bitmap for each); `sourceUrl` parses with `new URL`, protocol `https:`, host `docs.aws.amazon.com` or `aws.amazon.com`; ≥ 2 facts per kind and ≥ 2 for `dynamodb`. `pickFact(servicesUsed, seed)`: candidates = facts whose service has count > 0, in CATALOG_ORDER then file order; if empty, the dynamodb facts; index `seed % n`. Render uppercases the text.

**`Enter` maps to `start` on attract and `confirm` elsewhere.** The app sends `start(seed)` on attract and `confirm` on the incident, initials (as `initialsKey enter`), and high-score screens. While `playing`, the app does not send `start` or `confirm` at all, and the reducer ignores `start` outside `attract` anyway (defense in depth, CC-2.3).

**Game-over detection is phase-based (binding).** `src/app/main.ts` never scans `state.events` for game over. After every `engine.step` and after every QA mutator call it runs `if (state.phase === 'gameOver' && !session.gameOverSent) { session.gameOverSent = true; dispatch({ type: 'gameOver', summary, qualifies }) }`; `session.gameOverSent` resets when a `startEngine` effect creates a new game. This works for `forceGameOver` (called between steps, its event cleared by the next step) and for normal and time-limit endings alike. Audio still plays the game-over SFX from the `gameOver` event when present.

**`qualifies` is computed by the app** using the pure `ranking.qualifies(localList, score)` and passed in the `gameOver` event. That keeps the cabinet free of storage concerns.

**Non-qualifying remote submission (CC-8.2).** It uses `lastInitials ?? 'KIR'`, so a global score can still be recorded without forcing initials entry. It is emitted in the `reduce` result for the `confirm` that leaves `incident` for `highscores`.

**Timings in UI ticks (60 Hz).** INSERT COIN blinks with a 30-tick period, toggling every 15. The fast flash after a failed start toggles every 4 ticks for 60 ticks. The attract panel switches every 480. The incident lockout is 60. The initials idle timeout is 1800. The high-score screen dwells for 600.

## Edge cases (unit tests)

- A coin on every screen, including `playing` and `initials`.
- Start with 0 credits: no effects except the `sfx('denied')`, plus the flash.
- Coin at 99: `accepted:false` and the sfx `denied`.
- A second `gameOver` while already on `incident` is ignored.
- Confirm during the lockout is ignored.
- Initials: typed `'a'` becomes A; a typed digit or `'Ä'` is ignored; Up from A wraps to Z and Down from Z wraps to A; Left at slot 0 stays put; a typed letter in slot 2 doesn't advance past it.
- Offline: confirming initials emits no `submitRemote` and `remoteStatus` is `offline`.
- A tainted summary emits no `submitRemote` and leaves `remoteStatus = 'idle'`.
- An emitted `submitRemote` sets `remoteStatus = 'submitting'` in the same reduce result.
- A non-qualifying score > 0 that is tainted, or has more than 10000 events, emits no `submitRemote` (CC-8.2).
- The app's game-over check, implemented as the pure helper `checkGameOver(state, session) → boolean` in `src/app/session.ts` (returns true once and sets `session.gameOverSent`), fires once after `forceGameOver` and does not fire again on later frames (`src/app/session.test.ts`).
- Score 0 doesn't qualify, so the flow goes straight to highscores with no remote submission.

## Error handling

The reducers are total over their typed inputs and never throw. Unknown events in a given screen return the state unchanged with no effects, and nothing is logged. `pickFact` with an empty facts file is a build-time content error, so `facts.ts` validates the imported JSON at module load and throws `Error("aws-facts.json invalid: ...")`, which is fatal and caught by a unit test. Remote status updates arriving after the user has left the high-score screen are still stored but not shown.

## Invariant ownership

The credit range 0..99 is owned by `credits.ts`, the only code that computes credits. The cabinet calls it and never does arithmetic on credits itself. `^[A-Z]{3}$` is owned by `initials.ts` (letters stored as 0..25 indices, so invalid output is impossible by construction), and `ranking.ts` re-checks it at insert time.

## Testability

Everything here is a pure function and fully unit- and property-testable. Browser behavior is checked by the Playwright screenshots (arcade-presentation spec).

## Correctness Properties

| ID | Property | Requirement |
|---|---|---|
| P1a | For any initial credits 0..99 and any sequence of `coin`/`start` actions through `insertCoin`/`tryStart`: credits ∈ [0,99] always; `start` succeeds iff credits ≥ 1 before; a successful start lowers credits by exactly 1; a failed start leaves credits unchanged; `coin` raises credits by 1 capped at 99 | CC-1, CC-2 |
| P1b | For any sequence interleaving `coin`, `start(seed)`, and a synthetic round trip (generated only when `screen === 'playing'`: `gameOver({score: 0, …, tainted: false}, qualifies: false)`, then 60 × `uiTick`, then `confirm` (incident → highscores), then `confirm` (highscores → attract); on any other screen the round-trip action is skipped; score 0 means no remote submission) through the cabinet `reduce`: credits ∈ [0,99] always; `start` succeeds iff `screen === 'attract'` and credits ≥ 1 before; a successful start lowers credits by exactly 1, emits exactly one `startEngine`, and sets the screen to `playing`; any other `start` changes nothing; `coin` raises credits by 1 (capped at 99) on any screen | CC-1, CC-2, CC-2.3 |
| P9 | For any sequence of `InitialsKey`s (incl. arbitrary unicode chars), `initialsString` always matches `^[A-Z]{3}$` | CC-7.4 |
| P10 | For any `servicesUsed` map and seed, `pickFact` returns a fact for a used service (or DynamoDB when none were used), and repeated calls return the same fact | CC-6.1 |

All use `numRuns: PBT_RUNS` (200).
